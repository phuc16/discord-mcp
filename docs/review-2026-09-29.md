## Notes for the maintainer

- OAuth clients are always registered as public clients (no secret). Dynamic client registration is open and accepts any redirect URI, as the MCP authorization spec expects; the consent step is Discord's. Deployments that want to restrict this should put registration behind network controls.
- Rule actions marked `allow_destructive` run without a confirm token by design, and are audited under the actor `rule:<id>`.
- Bulk limiter tokens are taken before the dry-run step, so a `confirm_required` response consumes one bulk slot.
- `OPTIONS /mcp` preflight returns 401 (bearer middleware runs first), so browser-based cross-origin MCP clients cannot call `/mcp`.
